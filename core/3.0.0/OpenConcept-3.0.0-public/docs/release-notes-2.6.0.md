# OpenConcept v2.6.0 — 記録と履歴

ページの最新版に加え、発言・提案・判断・訂正の経緯を保持して参照する版です。保存処理、履歴検索、原本出力と隔離復元に及ぶ変更のため、パッチ版ではなく v2.6.0 としました。

## 利用方法

サイドバーの「記録と履歴」を開きます。単語、種類、期間で検索し、結果から原文と保存データを開けます。ページの変更履歴にも「原文を読む」を追加しました。ページ旧版・コメント・AI検索の会話・音声会話・取り込んだ発言・旧添付を扱います。

発言日時と記録／取込日時は別項目です。外部の日時にはタイムゾーンを必須とし、UTCへ正規化した値と入力値を保存します。不明な日時を取込日時で埋めません。旧来のDB日時には存在しないタイムゾーンを付与せず、記録日時として表示します。

「記録を追記」では、訂正・撤回・検証の記録・判断・観測を、自分の新しい記録として追加します。元の本文は変更されません。追記から対象へ、対象から追記へ移動できます。「検証」の区分を選ぶだけで独立検証済みになるわけではありません。

AI変更案の承認／却下／実行結果も別ターンに追記し、元の質問と提案を保持します。ファイルの削除は現行一覧からの取り外しとなり、旧バイトと所有・参照情報を保持します。ページの物理的な完全削除は無効化し、ゴミ箱で保管します。保存容量は履歴・旧添付に応じて増加します。

## クラウド会話の取り込み

「テンプレート」を取得し、サービスのエクスポートを共通JSON形式へ変換して取り込みます。v2.6.0は各社固有のエクスポートJSONを直接判別する変換器を含みません。変換元ファイルも保管してください。

```json
{
  "format": "openconcept-conversation",
  "version": 1,
  "source": "my-cloud-export",
  "conversation_id": "conversation-1",
  "title": "設備の設置案",
  "messages": [
    {"id":"m1","sequence":0,"role":"user","kind":"statement","text":"案Aを検討する。","occurred_at":null},
    {"id":"m2","sequence":1,"role":"assistant","kind":"proposal","text":"案Bも候補です。","occurred_at":"2023-01-01T10:00:00+09:00","parent_id":"m1"},
    {"id":"m3","sequence":2,"role":"user","kind":"correction","text":"設置条件のため案Bへ変更する。","occurred_at":null,"relates_to":"m1"}
  ]
}
```

`sequence` は同一会話内で重複しない0以上の整数です。`role` は user / assistant / system / developer / tool / unknown。`kind` は statement / proposal / report / observation / verification / correction / retraction / decision。訂正・撤回・検証には `relates_to` が必要です。親と関連先は同じ会話の先行発言を指定します。`speaker` は任意の発言者名です。省略した日時はnullになります。

1回4 MiB、最大10,000発言、1発言1 MiBまで。同じ所有者・source・conversation_id・発言IDの再取込は重複を作りません。既存IDの本文・役割・日時等の変更、重複キーや重複順序は拒否します。受け取った共通形式JSONの原バイトとSHA-256も保存します。

## 履歴を使ったAI検索

「履歴を根拠にAIへ質問」は現在のRAG接続方式と独立して履歴を検索します。通常のCore検索にも履歴候補を追加します。外部Custom RAGや別のCurrent Routeを選択している場合は、履歴画面のボタンを使用してください。

検索語の展開にLLMを利用できますが、記録の日時・順序・ID・関連は保存値で処理します。原文ID・ハッシュ・抜粋位置を回答に残し、回答生成前後と履歴表示時に現在の閲覧権限を検証します。根拠が不足する場合の一般知識への自動切替を停止しました。過去に保存した一般知識回答は判別可能なまま保持します。

履歴検索は最大20,000走査行／5秒／2,000一致件を上限とし、打ち切り時は画面に絞り込み案内を出します。無制限の全履歴ベクトル索引ではありません。LLMが返す文章の意味が常に正しいことを保証する機能ではなく、原文を確認できる根拠を維持する仕組みです。

## 正本出力と隔離復元

管理者は「正本と添付を出力」から `.oc.jsonl` を取得できます。ページ・ACL・改訂・コメント・必要な利用者属性・本体AI会話・共通形式の取込原文・訂正関係・音声会話・現行添付・保持済み旧添付を含みます。音声プラグインがOFFでも現存する会話を含めます。会話の通常閲覧は所有者に限定し、全正本出力は管理者専用です。

Coreスキーマ世代6と既存のDB構成を維持します。正本スナップショット契約はversion 2。既定の全Core範囲では `knowledge-history` providerを選択し、旧ファイル版も含みます。providerを明示指定するとその選択が優先されます。

JSONLのレコードとBase64の添付をSHA-256で検証します。ZIP拡張は不要です。作成時には内容検証までを行い、復元検証済みとは表示しません。スナップショット上限は2 GiB・100万レコード・取得120秒、保持TTLは1時間。HTTP実行時間やメモリの上限がより短いサーバーではCLIを使ってください。出力には暗号化や電子署名を施しません。非公開の保存先で管理してください。

```text
php scripts/knowledge-archive.php export 1 /private-backups/knowledge.oc.jsonl
php scripts/knowledge-archive.php verify /private-backups/knowledge.oc.jsonl
php scripts/knowledge-archive.php restore /private-backups/knowledge.oc.jsonl /private-backups/restore-check-260
```

exportの数値は有効な管理者の利用者IDです。出力ファイルは新規、親ディレクトリは既存を指定します。restoreは新しい隔離ディレクトリにSQLiteとuploadsを作り、全レコード・添付バイトの一致、外部キー、DB整合性を検証します。既存の保存先への上書きや稼働DBの切替は行いません。アカウントの資格情報は持ち込まず、復元先のログインを無効にします。復元検証から運用への切替、認証の再設定、索引の再構築は管理者の環境復旧手順として別途行います。

`.env`、APIキー、パスワード、セッション、運用設定、RAG索引は含めません。任意プラグインの独自原本や受理済みOCR補助本文は、この固定形式のアーカイブには含みません。環境全体の復旧用バックアップも継続してください。HTTP出力物は非公開storage/knowledge-exportsに残り、ダウンロード権限は1時間で失効します。不要な出力物の保管期限は運用側で管理します。

v2.5.0以前に既に消された履歴や、記録されなかった日時は復元できません。

## 更新

v2.5.0からの更新はファイルの結合だけで、CoreのDBスキーマ変更はありません。更新前に従来の環境全体バックアップを作成し、書き込みを停止して更新パッケージを適用してください。既存のプラグイン設定・利用者データは保持されます。
