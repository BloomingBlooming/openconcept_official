# OpenConcept V2.5.0

## 追加した機能

- Plugin API 1.0.0：原本の版・公開実績、イベント、排他ジョブ、設定・暗号化資格情報、検索用本文、受信ボックス、共通モーダル、ファイル状態、アプリ情報を共通化。
- AI File Reader 0.1.0：PDF（テキスト層・画像OCR）、Word（DOC/DOCX）、Excel（XLS/XLSX）。OpenAI Responses／GPT-5.6 Luna、またはマルチモーダルのOpenAI API互換接続を設定可能。
- 一度公開された原本版を、ログイン・閲覧後の別リクエストで読み取る。処理途中の中断は期限付きロックと再試行で回復する。検索リクエストはOCRを実行しない。
- 正常な抽出結果は通常のAI検索で利用する。失敗・要確認は管理者の受信ボックスから確認し、登録または破棄する。空の結果は登録できない。破棄後も原本は残り、ファイル一覧に「データ未登録」と表示する。
- システム管理者のログイン後に公式GitHub配布を確認し、新版があれば本人の受信ボックスへ通知する。既読後も同じ版の通知を重複させない。
- 将来のバックアッププラグイン向けに、正本DBと原本ファイルの読み取り専用スナップショットAPIを追加。RAGインデックス・チャンク・Embeddingは含めない。SQL／テキストへの変換プラグインと復元機能は今回の同梱対象外。
- 別配布の図面管理0.9.2で、訂正連絡の管理者受信トレイ通知、通知から図面・対象コメントへの移動、一覧の未対応表示、対応コメントと連絡者への通知を追加。既存の未対応連絡も通知へ補完する。
- 共通画面アクションに中止・画面切り替えを確認するcontextを追加。通知を閉じたり別のお知らせへ移ったりした後、遅延した応答で古い画面を開く問題を修正。
- 受信トレイに既読通知のアーカイブと件数付きアーカイブ一覧を追加。「すべて」「未読」「アーカイブ」を10件ずつ表示し、前後のページへ移動できる。アーカイブ内の削除は通知を非表示にする操作で、DB上の通知本文・履歴は保持する。

## 利用開始

本体にプラグインの最低対応版一覧を同梱し、その版以上を利用できる。対応表にないID・最低版未満、必要APIの不足、不正な設定ファイル、起動失敗は設定画面でエラー表示し、有効化を拒否する。エラーのあるプラグインは「取り外す」で実行対象から外せる。コードは退避し、登録データ・原本・設定・通知は保持する。使用中または接続設定のあるDBプラグインは取り外さない。最低対応版一覧は同梱のPlugin APIリファレンスを参照。

プラグイン一覧の読み込み時に新版を確認し、現在の本体に適合する候補だけに「UpDate」を表示する。更新は既存ON/OFF・設定・登録データ・原本を保持し、旧コードを退避して差し替える。取得・検証・配置の失敗は旧版を維持/復元する。更新版の番号を増やし、下位互換性または本体を止めない処理を保つことはプラグイン作者の原則とする。

「設定 → プラグイン」でAI File Readerを有効にし、サイドバーの「AIファイル読み取り」から接続を設定する。初期状態は無効、自動読み取りも停止している。接続確認に成功した接続で自動読み取りを有効にする。共通AI接続の再利用は明示的に選択する。

接続確認は文字画像だけを含む検証用PDFを送信する。選択した接続がPDF・画像を読み取れない場合は有効にならない。読み取りと接続確認には設定先のAPI利用料金が発生し得る。Excelは各シートの行をPHPで読み取り、範囲を分割して渡す。Wordの埋め込み画像・図表など、取得範囲を保証できない内容は要確認として扱う。

「保存済み接続をテスト」を押すとテスト中の表示が出て、完了後はボタン直上に成功・失敗の結果が残る。フォームを下へスクロールしていても結果を確認できる。失敗時は認証、利用制限、通信・TLS証明書、応答形式、画像読み取りなどの理由を表示する。テストは保存済みの接続を使うため、変更した接続を試す場合は先に保存する。

APIとの通信・応答取得に成功しても、全文の読み取りを確認できない場合は「接続成功・読み取り検証は未完了」と表示する。この状態では読み取り能力を検証済みにせず、自動読み取りを開始しない。

初期の通常AI検索は、受理済み本文を検索し、一定長のチャンクに分けて回答の根拠にする。回答前後と履歴表示時に現在の閲覧権限・公開状態・原本版を確認する。原本が非公開・削除・差し替えになったときは、古い結果を根拠に利用しない。読み取りプラグインを無効にしても、受理済みの検索用本文とファイル状態は本体に保持する。

訪問をきっかけに動くため、アクセスがない間は処理が進まない。初期値は1ファイル10 MiB、PDF60ページ、API応答60秒、1日100リクエスト。上限超過や読み取り失敗は確認対象になる。環境のPHP実行時間制限によって処理が中断した場合、次回の訪問で再試行する。

## 更新確認

取得先は `BloomingBlooming/openconcept_official` の `core/<version>/`。正式な数値版、配布ZIP、SHA-256ファイル、展開済み配布マニフェストを照合する。GitHub Releasesは利用しない。通常は1時間に1回まで、制限・障害時は再試行時刻を守る。一般ユーザーのログインやページ閲覧はGitHub照会を起動しない。

通知をクリックすると現在版、新版、確認日時、取得可能な変更点、公式配布・手順へのリンクを表示する。更新ファイルの適用は管理者が行う。

## V2.4.1からの更新

新規設置用は `OpenConcept-2.5.0-public.zip`。既存V2.4.1には `OpenConcept-2.5.0-upgrade-from-2.4.1.zip` の手順を使用する。

1. アプリへの書き込みを停止し、DB、原本添付、設定・資格情報を含む既存環境全体をバックアップする。
2. 同梱READMEに従い、差分パッケージの `files/` の内容を既存ルートに結合する。独自変更があれば事前に比較する。
3. 初回起動で正規のスキーマ世代5から6へ移行する。新規のCoreテーブル4個を追加し、既存テーブルのデータを保持する。
4. 管理者ログイン、既存ページ・添付・プラグイン設定を確認し、必要ならAI File Readerを有効にする。

スキーマ移行後にV2.4.1へ戻す場合は、コードだけを戻さず、移行前の環境バックアップから復旧する。配布物には利用者のDB・添付・設定・秘密鍵を含めない。

## プラグイン開発

入口は `plugin.php` に渡される `$context['plugin_api']`。PHPコードを隔離するサンドボックスではなく、信頼されたローカルプラグインの共通契約である。マニフェストでAPI版と必要な能力を宣言し、互換性のないプラグインは起動しない。

正本読み取りは `canonical.export` を宣言した有効なプラグインと、現在有効なシステム管理者に限定する。既定の正本出力にはユーザーのパスワード、資格情報、RAG派生物を含めない。`extracted-content` を明示指定した場合だけ受理済みOCR本文を補助データとして含める。これはコンテンツ移送用の契約であり、環境全体の復旧バックアップとは出力範囲が異なる。

原本バイトの初期出力範囲は現在のファイル一覧に登録された版。差し替え前の復旧用バイト・旧版管理記録はmanifestで対象外として示す。過去の原本版を含む環境全体の復旧には、DB・storage全体の従来バックアップが必要。
